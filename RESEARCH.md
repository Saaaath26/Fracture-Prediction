## Dataset policy

All original images, annotation formats, notebooks, model weights and CSVs are preserved. COCO is the explicit canonical source for new detection/segmentation conversion; original YOLO, VOC and VGG files are retained, not silently merged. COCO image dimensions must match the decoded image. Fracture instance segmentation is **not** anatomical segmentation.

The default 574/82/63 split follows the downloaded dataset's 719 fractured cases. The repository notebook test CSV has 61 cases: it omits IMG0003375.jpg and IMG0003376.jpg. This discrepancy is retained and documented, so the default is not claimed to exactly reproduce the notebook split. It leaves 3,364 non-fractured cases unassigned. It is unsuitable for measuring normal-case specificity. Preparation intentionally fails on audited errors, including truncated images, dimension mismatch, and duplicates crossing splits. The full original data cannot currently pass this gate.

For a future reviewed cohort, create a CSV outside the dataset with columns:

```csv
image_id,patient_id,split
```

Populate with verified patient IDs, use `train`, `val`, `test`, and assign all studies/views/duplicates of a patient to the same partition. Add `split_manifest: "../reviewed/splits.csv"` to a copied experiment YAML. This explicitly selects a cohort without altering the source; audit reports the excluded count. Include reviewed normal cases for a normal-versus-fractured experiment. Do not infer patient identity from sequential filenames. Remove/exclude or reacquire corrupt cases and resolve annotation geometry under expert review. A curated manifest is a real data requirement, not a supplied synthetic example.

Metadata is not proof of patient independence. Exact byte and decoded-pixel hashes are checked; 64-bit dHash collisions are review candidates, not an exhaustive near-duplicate test. Review repeated views, multiscan images, hospital/device confounding and laterality. Patient-level separation remains mandatory for relationship and neural manifests. Original-split YOLO runs require a separate explicit acknowledgement if patient identity remains unavailable; this does not waive corrupt-image or exact-duplicate errors.

## Experiments

Four configs cover YOLO11 and YOLO26 detection and fracture instance segmentation. The nano checkpoints are defaults; `n/s/m/l/x` names are validated. Paths resolve relative to the YAML file, accept spaces, and outputs cannot be inside the original dataset. Config validation is pure metadata validation and does not construct a model or download weights.

After correcting the cohort, `fracatlas prepare --config ...` creates isolated copies, task-specific labels, dataset YAML and provenance with file hashes. It refuses to overwrite an existing prepared directory. YOLO11/26 of the same task may share prepared data. Training checks these hashes before loading a model.

All future fitting entry points require `--authorize-training`. Importing a module, auditing, extracting geometry, running tests or opening the dashboard never initiates training. See [future commands](docs/FUTURE_TRAINING.md); **none were executed**.

## Contours and feature interpretation

Classical extraction uses grayscale percentile normalization, CLAHE, Gaussian smoothing, Otsu thresholding for bright bone candidates (or a low-intensity foreground envelope for soft-tissue candidates), morphological closing and external contour tracing. Candidates touching the image boundary or occupying more than 90% of the frame are rejected for geometry. Minimum area is configurable in the Python API. An accepted contour means geometrically usable, **not verified bone identity**. Labels, implants, overlapping anatomy, exposure and cropping can all confound the algorithm.

Features include area, perimeter, centroid, circularity, solidity, oriented bounding-box axes, aspect ratio and orientation. Verified `(x,y)` pixel spacing can be supplied to the geometry API for area/perimeter in physical units; no spacing is inferred from JPEG resolution. There are no clinical fracture-risk thresholds. Fracture–contour relationships include signed fracture-centroid distance to the candidate boundary and fracture-mask overlap fraction. Absent fracture annotations return explicit absent/null values.

Each JSON feature record carries schema version, source hash, contour type, coordinate points, method parameters, warnings, uncalibrated uncertainty and clinical-validation status. See [schema](docs/FEATURE_SCHEMA.md). Invalid candidates are reported separately. The supplied `reports/example_features.json` is deterministic geometry from one real image, **not a model prediction or performance metric**.

## Relationship and optional neural workflows

`export-table` converts feature JSON files plus a reviewed contour-selection manifest into geometry CSV. Selection is explicit: a reviewer selects one appropriate contour per image; the software does not guess anatomical identity by choosing the largest component. The manifest has `image_id,patient_id,split,label,contour_id`. Header-only templates are in `configs/`; no labels or patient identities are invented.

Logistic regression and XGBoost use explicit geometry feature lists. Imputation and scaling fit only on training rows. Validation uses a fixed probability threshold; a separate command evaluates the held-out test set. Target-derived fracture labels/counts, mask overlap and boundary distances are barred from fracture-presence classifier inputs to prevent circular evaluation. Spatial relationship exports remain available for descriptive studies or a separately designed, independently labeled outcome. The current supervised target is fracture presence, not clinical risk or prognosis.

U-Net requires aligned expert-verified binary anatomical masks, source provenance and patient-disjoint splits. Bone and soft-tissue models must be separate. Siamese CNN requires independently verified pair labels, both patient IDs and pair semantics established before use; it is an optional experimental pair classifier. The compact CPU trainers save the lowest-validation-loss checkpoint; no optimizer or training loop has been exercised during implementation. Neural prediction and evaluation adapters are included.

nnU-Net preparation exports verified PNG images/masks, dataset JSON and custom split JSON. External planning/training uses official nnU-Net CLI commands. No nnU-Net planning, preprocessing or training has run.

## Evaluation and limits

YOLO evaluation delegates detection AP and instance-segmentation metrics to Ultralytics. U-Net evaluation reports per-image Dice/IoU and macro means; two empty masks score 1 and empty-case flags are retained. Classifiers report confusion counts, sensitivity, specificity, AUROC and average precision; undefined single-class AUROC/AP are null. Siamese evaluation follows binary pair labels. Reports share task, split, schema version and provenance. Test sets are not used for fitting or threshold selection. Patient-level confidence intervals, external-site validation and clinical calibration are future study work, not claimed outcomes.

RGB/smartphone integration currently consists of structured exports only. Any cross-modality transfer is **experimental and unvalidated**. Radiographic pixel geometry cannot establish external RGB bone shape or smartphone fracture diagnosis.
